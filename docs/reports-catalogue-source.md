# Fydr report catalogue

Draft, 12 Sept 2026. One row per report. Everything marked **confirm** is a decision for Isabella or a fact for Claude Code to check in the code. Nothing here should be built until its definition sentence is agreed, because the definition is what a club will argue with.

All five use the approved report shell from PATTERN-S7: title, definition sentence, period and group, figure with denominator, at most one chart, table, export and print.

---

## 1. Training report

**The question:** how much work has the squad done, and who is above or below the group?

- **Shape:** longitudinal load. Charts carry the meaning, the table supports them.
- **Rows:** athletes. **Columns:** confirm against the built page (it already has extra selects and heat bands).
- **Definition sentence (draft):** "Session load is RPE multiplied by session minutes, summed over the period. Only sessions an athlete was expected at are counted, and a session with no rating is not counted as zero." **Confirm.**
- **Roles:** sport scientist, S&C, coach. **Confirm** whether the coach sees individual load or group means only.
- **Chart:** load by week, with the squad band. Suppressed below five athletes with data.
- **Export:** rows as shown, with the definition in the header.
- **Open:** is load stored or derived? Where does "load 2,910" on a week template come from?

## 2. Match report

**The question:** what happened around one match?

- **Shape:** per event. Rows are athletes for one fixture.
- **Content:** availability going in (full, modified, unavailable, with restrictions), who played, minutes, GPS if the club is on premium, RPE after, and any injury recorded on the day.
- **Definition sentence (draft):** "Everything recorded against {fixture}, from the squad as it stood at kick-off." **Confirm.**
- **Roles:** coach, sport scientist, medic. Clinical detail stays medic-only, as everywhere.
- **Chart:** none by default. A number per athlete is more useful than a chart of eleven.
- **Export:** one file per match, named with the opponent and date.
- **Open:** does the app record who played and minutes at all? If not, this report is availability plus RPE plus GPS only, and should say so rather than showing blank columns. **Likely the biggest gap in this list.**

## 3. Squad weekly report

**The question:** what does a head coach or a committee need to know about last week?

- **Shape:** a digest with sections, not a single table. This is the one that gets printed and emailed.
- **Sections:** availability now, compliance for the week, athletes needing attention, injuries opened and closed, load by group, sessions completed against planned.
- **Definition sentence (draft):** "The week Monday to Sunday, club local time. Each section states its own denominator." **Confirm.**
- **Roles:** all staff. Clinical detail medic-only, so the coach's copy names availability without reasons.
- **Chart:** at most one, load by group.
- **Export:** the natural weekly email. If notifications are built, this is what goes out on a Monday morning.
- **Open:** does a week boundary exist and is it shared with RPE and the nutrition check-in? Same question as the schedule board.

## 4. Athlete report

**The question:** how is one athlete doing over a block or a season?

- **Shape:** per athlete. Rows are dates.
- **Sections:** availability history, wellness trend, load, gym progress with personal bests, test results, nutrition adherence if the club uses it.
- **Definition sentence (draft):** "Everything recorded for {athlete} between {start} and {end}. Sections with no data say so rather than showing zeros." **Confirm.**
- **Roles:** sport scientist, S&C, coach (no clinical), medic (full). **Confirm** whether the athlete can export their own, which is also the simplest answer to a subject access request.
- **Chart:** one per section at most, following the analytics rules: zero-based axes for volume, squad band, suppression below the minimum.
- **Export and print:** this is the one that leaves the club. It may go to the athlete, a parent, or a university. It must carry the confidentiality line when it contains medical detail, and the medic's version must be visibly distinct from the coach's.
- **Open:** under-18 athletes. If a parent or guardian receives this, what may it contain?

## 5. Testing report

**The question:** where is the squad on its physical tests, and who has improved?

- **Shape:** squad over a period, with benchmarks.
- **Rows:** athletes. **Columns:** one per test, latest result, change since the previous test, position-relative percentile, and whether it is a personal best.
- **Definition sentence (draft):** "The most recent result for each test inside the period. A test with no result in the window is not shown as zero, and an athlete who has never been assigned a test does not appear for it." **Confirm.**
- **Roles:** sport scientist, S&C, coach.
- **Chart:** none by default. Percentile bars in the table carry it, as on the athlete profile.
- **Export:** rows as shown, with "lower is better" noted per test where it applies.
- **Open:** are tests assigned, and can "never assigned" be told apart from "no result"? Carried from the My data board.

## Rules that apply to all five

- The definition sentence appears on screen, in the print view and in the export header.
- Every figure carries its denominator, and exclusions are stated in a full sentence.
- Missing values are words, never zeros.
- Lowest or worst first, never alphabetically, wherever there is someone to chase.
- Below five athletes with data, rankings, shading and charts are suppressed; the figure stays.
- Clinical detail is medic-only, and a restriction line never names a diagnosis or a protocol.
- Every export is logged (who, when, scope, rows). Exports containing medical detail carry the confidentiality line.
- The print view and the exported PDF are one document.

## What to decide before building

2. Which reports does the pilot club actually need in week one? My guess: squad weekly, training, and athlete. Match and testing can follow.
3. Can an athlete export their own athlete report? If yes, it doubles as the subject access route.
4. Who receives the squad weekly report, and does it go out automatically on a Monday?

# Addendum, 13 September 2026: the seventh report, naming, and four sentences

**Approved by Isabella. These sentences are confirmed, not drafts, and carry the
same authority as the five above.**

## The training report was two reports

What is built as "the training report" is a per-session GPS board. The catalogue
above describes an RPE-times-minutes load report that was never built. Both are
wanted, they sit on opposite sides of the tier line, and **neither keeps the
name "Training report", because that name is the ambiguity.**

| Report | Tier | Name |
|---|---|---|
| The per-session GPS board that exists today | Premium | **GPS report** |
| The RPE-times-minutes load report, to be built | All clubs | **Training load report** |

## Definition sentences, confirmed

**GPS report** (premium)

> Per-session GPS totals for each athlete, from the files imported for that
> session. An athlete with no GPS file for a session shows as no record, never
> as zero.

**Training load report** (all clubs)

> Session load is RPE multiplied by session minutes, summed over the period.
> Only sessions an athlete was expected at are counted, and a session with no
> rating is not counted as zero.

Its off state, since RPE is now a club setting:

> This club does not collect session RPE, so there is no load to report. A sport
> scientist can switch it on in Settings.

**Compliance report**

> The share of expected entries that were submitted, over the period. An entry
> counts as expected only where the schedule or the club's settings asked for
> one, so a day nobody was asked about is not counted against anybody.

**Injury and availability report**

> Every injury open at any point in the period, with each athlete's availability
> as it stands today. Diagnosis, mechanism and clinical notes appear only in the
> medic's copy.

## One rule that comes with the compliance sentence

Compliance now spans wellness, RPE and nutrition, and RPE can be switched off,
so one club's denominator is not another's. **The report must state which entry
types it counted**, or two clubs will compare figures that are not the same
measurement.

## Absence

Which of the seven a club can see, and how absence reads, follows
`docs/decisions/absence-rule.md`: premium absence is silent, setting-driven
absence keeps the destination and shows an off state, and an empty report says
so with its denominator.
