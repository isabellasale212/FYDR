# Me

## 1. Where it sits

Tab 4 of 4. Route `/me`.

**Redrawn 8 September 2026** from the redesign reference (screens 11 and 12).
This file describes the screen after that change; §13 records what was removed
and the two things the reference asked for that were not done.

## 2. Who reaches it and when

Every athlete.

## 3. What you see

Their photo or initials at 58px with their name, position, team and squad number;
a Theme control (Light / Dark, a segmented pill); two stat tiles, wellness entries
this week and latest body mass; a password change; one settings card of five rows;
and Sign out as a full-width pill below it.

The settings card's rows, in order: **Notifications** (`morning wellness prompt` /
On or Off), **Leaderboard** (`you choose to appear` for a minor, `you appear
unless you leave` for an adult / Opted in or Opted out), **Units** (`weight and
distance` / `kg · m`), **Export my data** (CSV), **Report a problem**. Every value
except Units is read from the database on each render.

**Units is the one static value on the screen and is not a preference.** There is
no units column anywhere in the schema; the app is kilograms and metres
throughout, and the row states that rather than implying a setting. The reference
draws it as a row like the others; it has no chevron here, because it goes
nowhere.

## 4. What the athlete enters here

## 6. Every thing you can act on

| Element | Where | What happens | Takes you to | Writes | Confirm | Hidden when |
|---|---|---|---|---|---|---|
| Change password | Body | Re-authenticates, then updates | stays | `auth.users` | yes, current password | never |
| Export my data | Body | Downloads a CSV | `/me/export` | an `audit_log` row | no | never |
| Notifications | Row | Opens settings | `/me/notifications` | nothing | no | never |
| Leaderboards | Row | Opens settings | `/me/leaderboards` | nothing | no | never |
| Units | Row | Nothing. Not a control, and carries no chevron | n/a | nothing | n/a | never |
| Sign out | Bottom, below the card | Ends the session | `/login` | nothing | UNVERIFIED | never |
| Report a problem | Row | Opens the form | `/report-problem` | nothing | no | never |

**Report a problem is now reachable only from here.** Today's "Something not
right?" row was removed by the same redesign, so this row is the sole route to
`/report-problem` — which is why it was kept when the reference's settings card
does not draw it. Same for Export my data, which is the Article 20 route
(`me/export/route.ts`).

**There is no tier gate on this screen any more.** This file used to say "this is
the only tier gate in the entire athlete shell", pointing at `isPremium(tier)`
guarding the Apple Health toggle. That claim is now wrong twice over: the toggle
is gone (§13), and the athlete shell gained a real tier gate elsewhere on
8 September 2026 — `gpsMetricBlocked` on `/my-data/boards` and
`/my-data/boards/[leaderboardId]`, which keeps GPS-derived leaderboards off a
Basic club. `compute_leaderboard` enforces the same rule server side (migration
0094).

## 9. Permissions

**Resolved.** This screen used to ask for a permission that led nowhere — Apple
Health wrote an `athlete_consents` row and nothing read it to ingest anything.
DECISION 4 / Q-03 settled it on 8 September 2026 (hide it until ingestion exists)
and it is built: nothing on this screen asks for that permission now. Existing
consent rows were left alone rather than withdrawn on athletes' behalf; see
`decisions-required.md` DECISION 4 for the three things deliberately not done.

The two settings rows read state the athlete owns and nobody else does — their own
`notification_preferences` rows and their own leaderboard consent / opt-out. The
leaderboard row applies the same age rule as `/me/leaderboards` itself (under 18
is opt-**in**, 18 and over is opt-**out**, and an absent date of birth counts as a
minor), from the same `date_of_birth`, so the row and the screen it opens cannot
state different regimes.

## 10. States

Loading, error. **Basic and Premium clubs now see the same Me screen** — the tier
gate that made them differ was the Apple Health toggle.

Per-row states: Notifications On / Off; Leaderboard Opted in / Opted out, over two

An "off" value takes muted ink at weight 400 (`.me-row .v[data-off]`), measured
5.97:1 in light and 7.09:1 in dark.

## 13. What the 8 September redesign removed, and what it asked for and did not get

**Removed**, per the reference:

| Gone | Was | Consequence |
|---|---|---|
| Photo / avatar-colour picker | `AvatarUploadForm`, writing `users.avatar_url` and `avatar_colour` via a Storage bucket (migration 0030) | An existing photo still shows in the header here and on Today. Nothing sets one any more. The component and `lib/queries/avatar.ts` are still in the tree, unreferenced. |
| Edit profile form | `AthleteProfileEditForm`, writing `users.preferred_name` and `phone` (migrations 0027-0029) | Same: still in the tree, unreferenced. An athlete can no longer change their own preferred name or phone number anywhere in the app. |
| Apple Health card | The consent toggle plus its Premium gate | DECISION 4, resolved. The staff Settings row's copy was corrected in the same commit, because it told coaches athletes turn this on here. |
| Version footer | `Fydr v1.0` | None. |

**Asked for by the reference and deliberately not built**, both because a
decision taken the same day outranks a drawing:

- **An "Apple Health / Not connected" row.** That is Q-03's option (b). Option
  (a) — hide it until ingestion exists — is what was confirmed, so the row is not
  there. One line to add if that is overturned.
- **Removing the password form.** Q-02, decided the same day: a player "can change
  their own password and use the email-linked reset flow, and nothing else
  affecting the account itself". Password change is one of exactly two things an
  athlete may do to their own account; removing the form leaves only the
  forgotten-password email, so an athlete wanting to change a password they know
  would have to claim to have forgotten it. Kept.

**Shape.** Sign out and both halves of the Theme control are the first athlete
controls drawn as full pills. They read `--r-full` (999px) and are named in
`ATHLETE_PILL_EXEMPT` in `scripts/check-control-radius.ts`; every other
interactive rule in the app still has to read `--r-control` (6px) or fail the
build, and a raw `999px` on an exempt name still fails. The staff app keeps 6px
controls throughout, so the two surfaces now diverge on purpose.
