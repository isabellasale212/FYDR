# Archive: superseded athlete specification documents

Nothing in this directory is current. Each file is kept because it is the only
record of how a decision was reached, not because it describes the app.

**The live specification is the markdown under `docs/athlete/`**, and
`docs/generated/Fydr-Athlete-App-Specification.docx` is built from it by
`scripts/build-athlete-spec-docx.py`. If those two ever disagree, the markdown
wins and the docx needs regenerating.

---

## `2026-09-08-athlete-spec-review-record.docx`

**What it is.** The two-pass review of the 7 September specification, carried out
on 8 September 2026 by Claude and Isabella working from the document alone, then
completed by Claude Code against the live repository. Every change in it is a
tracked change under one of two author names — `Claude` for the document review,
`Claude Code` for the repository pass — so Word's revision history is the record
of who established what.

**Why it is archived rather than deleted.** Its *content* has been absorbed into
the markdown, so it is no longer needed to know what the app is. What cannot be
absorbed is the reasoning trail: the recommendation that was drafted, the
decision Isabella took against or alongside it, and in three places the decision
she reversed the same day. `open-questions.md` now carries the answers; this file
carries how each was arrived at, and the order it happened in.

**What it holds that the markdown deliberately does not:**

- **Per-question revision history.** Each of the twenty-seven questions shows
  Claude's drafted recommendation, then Isabella's decision, then — for the nine
  closed on 8 September — Claude Code's answer from the repository. The markdown
  keeps only the settled answer.
- **The native iOS reversal, as it happened.** The commitment to build a native
  iOS app was made and withdrawn on the same day. The docx shows the commitment
  struck through and the correction inserted in three places; the markdown states
  only the settled position, which is Stage A0's original web-only Option C.
- **Two crossed edits.** Two independent corrections of the same iOS paragraph
  were made minutes apart and merged. The merge is visible here and invisible in
  the markdown.

**Do not edit this file.** It is a dated snapshot. If something in it is wrong,
the fix belongs in the markdown, which is what anybody builds from.
