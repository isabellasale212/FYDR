The rule this board is built on

A logged set keeps the prescription it was logged against

The logger reads “Prescribed 100 kg · +2.5” beside what the athlete actually did, so the prescription is the reference the set is measured against. Editing a block mid-week must not move that reference under a set already logged. Every edit screen on this board says, in words, that logged sets keep their own numbers and future sessions take the new ones. Whether the data holds a per-set prescription snapshot is the first item under Open against code.

Nothing the logger needs is optional

Seven fields, and two of them live on the exercise

Order, exercise, sets, reps, load and rest are written per row. The weight step and whether a weight exists at all come from the exercise record, so the editor shows them as read values rather than inputs, and a bodyweight exercise says “logs reps only” where its load would be. A row cannot be saved with a blank in any of the six.

An adjustment is a third column

The club programme is read-only on the adjust screen

Adjusting for one athlete opens a screen where the club values sit in a read-only well and the athlete’s own column sits beside them, carrying a required note. There is no control on that screen that can write back to the block, which is how the override rule is enforced by shape rather than by a warning.

Open against code

Is the prescription stored against the logged set, or read from the programme?

This is the one the board depends on. The logger renders “Prescribed 100 kg · +2.5”, which requires the prescribed weight, reps and step as they were at the moment the set was logged. If the set row holds only actual weight and reps and the reference is joined live from the programme, then editing a block silently rewrites history and every screen on this board is making a promise the data cannot keep. Confirm that a logged set carries its own prescribed values; if it does not, that is a migration, not a design change.

Can a load be a percentage of a one-rep max, and what does it resolve against?

SC-24a renders a Load cell reading “70%” and the profile board renders e1RM as a dash with “needs three logged top sets in the block; there are two”. So the field accepts a percentage and the reference can be absent. Confirm whether the percentage resolves to kilograms per athlete from e1RM, whether a tested 1RM can be entered, and what the logger shows when the reference is missing. The board assumes a dash and says so.

What does the exercise record hold, and what are the fields called?

The approved logger board names weight_increment, unit and has_load as per-exercise data and shows 2.5 kg, 1.25 kg and a bodyweight exercise. “Each side” is rendered in the logger as “10 each”, which implies a unilateral flag. No capture shows the exercise library itself, so the field list and the library’s own screen are spec, not observation.

Does an assignment carry a start and an end date?

The profile board renders “In-Season max · week 2 of 4 · ends Tue 29 Sept” and the programme list renders “2 athletes · 1 day”, so a block has a position in a run of weeks and an end. Whether those dates live on the assignment or on the programme decides whether two groups can run the same programme on different dates. The assign screen assumes the assignment holds them.

What can an override change, and is its note required?

The captured programme table has an Override column per exercise row and the nutrition list says “1 override active”, so overrides exist at exercise level on both sides. Whether an override may change sets and reps as well as load, whether it can add or remove an exercise, and whether the note is enforced server side are not observable. The board makes the note required and the scope one exercise row.

Does editing a session write a revision, and can the previous version be read?

The product’s rule elsewhere is that a correction writes a new dated revision and never overwrites. The confirmation screen states that for a programme edit — Owen Hartnell, Fri 11 Sept 11:20, previous version readable in history. No capture shows a programme history, so both the revision and the screen that reads it are open.

Which nutrition rules exist as fields, and at what precision?

The SS-23 capture shows four steppers: protein, carbohydrate, fat and fluid, with carbohydrate periodised across three day types. The profile board shows Adam’s resolved targets as 167 g protein and 387 g carbohydrate at 104.2 kg with kcal and fat as dashes — which implies energy is a fifth rule that can be empty rather than a derived figure, and a carbohydrate rule of 3.72 g/kg. The board renders 3.72 and 1.60 as back-derived values. Confirm the stored fields, their precision, and whether energy is a rule or a calculation.

Which day type does an athlete’s screen use, and who sets it?

Carbohydrate is periodised across training, match and rest days, and the athlete app shows one number. Whether the day type is derived from the published schedule, set per athlete, or chosen by the athlete is not shown in any capture. The resolved artboard labels the day type it is showing and claims nothing about where it came from.

Is fluid a plan rule that reaches the athlete?

Fluid is authored in ml per kg in the capture, but the profile board’s four resolved tiles are kcal, protein, carbs and fat — fluid is not among them. Either the athlete’s targets omit fluid or the profile panel is showing four of five. The board resolves fluid in the sentence and leaves it out of the tiles to match the approved panel.

For a coach, is Assign absent or rendered inert?

COACH-23’s caption says a coach holds MEAL_LIBRARY_EDIT but not NUTRITION_EDIT, so “New plan”, “Create” and “Assign” are absent — but the capture itself renders Assign and the steppers in a dimmed state. The approved read-only pattern says a control a role cannot use is not rendered at all, so the coach frame omits them and keeps Food library. Confirm which the code does.

SS-24 is captured as the sport scientist and shows “Edit this programme →”. MEDIC-24 states the medic holds REHAB_PROGRAMME and PROGRAMME_AUTHOR but not PROGRAMME_EDIT, and SC-24a states INJURY_PROGRAMME_PROPOSER belongs to the S&C alone. Does approval create the assignment, and does a rehab block have an end?

PATTERN-S3 treats approve as approve-and-assign and the S&C’s list renders “Approved Fri 4 Sept 11:02 by Ruth Callaghan · assigned”. This board follows that: the approved proposal appears here as an assignment with no action. Whether assignment is a second step, and whether a rehab assignment ends on a date or on a clearance, are both open.

Is there an assignment count, and how are groups and named athletes deduplicated?

The captures show “2 athletes” and “15 athletes” on a programme and “29 athletes assigned” on nutrition, so a count exists per programme and per screen. Nothing shows an assignment being made, so the distinct-athlete arithmetic, the “already on another programme” list and the unavailable-athlete line are designed here.
